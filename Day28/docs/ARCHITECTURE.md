# Architecture – Israel Knowledge Assistant (final, Week 4)

## One-liner

A FastAPI service whose core is a **LangGraph workflow**: deterministic guardrails and routing first, exact tools for arithmetic/listing, FAISS-backed retrieval-augmented generation for knowledge questions, per-session SQLite memory, uniform failure handling, structured observability with cost tracking, and a judged evaluation harness - packaged with Docker files and CI.

## Request flow

```text
Client ── POST /rag/graph {query, session_id?} ── X-API-Key + rate limit + Pydantic validation ── request id assigned
   │
   ▼ LangGraph
 receive_query ── blank ─────────────────────────────────────────────────────────────► END
   ▼
 input_guard ── unintelligible / prompt-injection ──► BLOCKED reply (nothing stored, no API calls)
   ▼ (session_id?) load_memory ─► contextualize (rewrite follow-up: LLM only when needed)
 route_query   rules by default | LLM optional        writes route, query_type, reason, routed_by
   ├─ direct   ─► direct_answer                                    0 API calls
   ├─ fallback ─► fallback_response                                0 API calls
   ├─ tool     ─► select_tool ─► run_tool ─► tool_answer           0-2 LLM calls (rules pick obvious tools)
   └─ rag      ─► retrieve_context ─► call_llm                     1 embedding + 1 LLM call
 any failing node (after retries) ─► fallback_node (honest message + best evidence)
   ▼
 output_guard   answer contract · no prompt leak · no number that is absent from the sources
   ▼
 finish ─► save_memory (turn + durable facts; never errors/blocked input) ─► END
   ▼
 response: answer, source, route, timings, usage (tokens, $), retrieved chunks, trace  (+ X-Request-ID)
```

The compiled graph's own diagram: [`graph.md`](graph.md) (generated by `python -m scripts.draw_graph`).

## Design decisions and the evidence behind them

| Decision | Why | Evidence (measured on this project) |
|---|---|---|
| Refuse **before** the LLM when retrieval is weak | cheapest, safest hallucination control | 0 % hallucination on 12 unanswerable/adversarial/trap cases |
| Numeric grounding on output | invented figures are the most damaging error | blocks invented 500 m / 85 % / year 73 in tests; found and fixed a citation-format false positive |
| Rules before LLM for routing/tools/guards | free, deterministic, explainable | route accuracy 100 % (22 msgs); complexity 93 % vs LLM 100 % (extra ~1 s/call) |
| FAISS with normalised vectors | thresholds keep the cosine scale; index persists | search 19.6 ms → 0.29 ms (≈ 65×) on 77 chunks |
| Topic-prefixed embeddings, topic boost, adaptive cutoff | precision of retrieved context | precision 0.43 → 0.91, chunks sent 3.7 → 1.6 |
| Sibling-chunk expansion | the answer sentence is often in a neighbour chunk | eval accuracy 82 % → 100 % |
| One retry layer (`OPENAI_MAX_RETRIES=0` + tenacity) | stacked retries multiplied a failure from ~9 s to 25 s | live failure drills |
| Schema not repeated in the prompt | strict JSON schema is enforced by the API | −28 % input tokens, −16 % cost, same accuracy |
| SQLite memory, bounded, not storing errors | durable, transactional, no infrastructure | restart-survival and injection tests |
| Prompt v1 kept over stricter v2 | tie on 36 judged cases → simpler wins | pass rate 0.972 both |

## Known limits (be upfront about these)

- **Small, clean, English data** (77 chunks / 53 documents, 3 deliberately fictional): results demonstrate *regression safety and design*, not scale. A perfect score on 22-36 cases is easy; it cannot rank strong systems.
- Guardrails are rule-based: paraphrased, obfuscated and non-English injections are **not** caught (documented, measured: 4 of 27 cases).
- Judge and system share a model family; LLM output text is not bit-stable even at temperature 0 (17/22 identical, verdicts identical).
- Docker files and the GitHub Actions workflow were validated by simulation (Docker is not installed here; nothing was pushed), not by a real build/run.
- Memory, rate limiting and the SQLite file assume a single process/node.
- Prices in `usage.PRICES` are estimates.
